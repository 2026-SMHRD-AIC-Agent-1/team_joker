# Chat Shield UI 개편 v3 설계안 — "캡스톤" → "운영되는 B2B 진단 SaaS"

작성 2026-09-09 · **승인 대기(코드 미수정)** · 선행 문서 [[chatshield-화면개편]] [[chatshield-게이팅]] [[chatshield-실패경로]]

## 0. 이 개편의 한 줄

**화면을 "우리 모델이 얼마나 좋은지 보여주는 리포트"에서 "당신의 지시문에서 발견된 항목 N건을 처리하는 작업대"로 바꾼다.**
새 데이터는 만들지 않는다. 지금 DB 에 있는 `round_no` × `verdict` 를 화면 언어로 번역할 뿐이다.

## 1. 실측으로 뽑은 심각도 — 3단계가 아니라 5단계다 ★

지시하신 3단계를 실제 DB(`joker.db`, 진단 123건)로 검증했더니 **분류에 안 잡히는 행이 2종 더 있었다.**

```
전체 진단 pair 기준 (defense_level IS NULL = 신규 진단 행만)
  🔴 미해결      r1 leak  → r2 leak     533건
  🟡 해결됨      r1 leak  → r2 block   2378건
  ⚪ 영향 없음   r1 block → r2 block   1876건
  🟠 처방 후 신규 유출  r1 block → r2 leak    99건   ← 3단계에 없다
  ⚫ 재진단 없음  r2 행 자체가 없음      836건   ← 3단계에 없다 (round1만 있는 런)
```

- **🟠 99건은 진짜다.** 처방문이 지시문을 바꾸므로 r2 응답은 r1 과 다른 문장이고, 원래 막히던 공격이 뚫릴 수 있다.
  3단계로 그리면 이 99건이 **어느 칸에도 안 들어가 조용히 사라지고, 카운트 합이 전체와 안 맞는다.**
  화면에서 "합이 안 맞는 표"는 심사에서 제일 먼저 잡힌다.
- **🟠 는 오히려 우리 편이다.** "처방이 만능이 아니라 새 구멍을 낼 수도 있어서 우리는 재진단을 한다" 가
  garak(진단만 함) 대비 차별점의 실증이다. 0건이면 그냥 0으로 표시된다 — 지어낸 칸이 아니다.
- ⚫ 는 `comparable=false` 또는 엔진 중단 시 나온다. `comparable` 경고 배지와 같은 사실을 행 단위로 말한 것.

### 실제 진단 1건 예시 (run_20260909_100819_a662 · 등급 A · 57.9% → 3.5%)

| 상태 | 건수 | 예 |
|---|---|---|
| 🔴 미해결 | **2** | AUTH-06, ROLE-01 |
| 🟡 해결됨 | 31 | AUTH-01, FORMAT-02 … |
| ⚪ 영향 없음 | 24 | AUTH-02, INDIRECT-03 … |
| 🟠 처방 후 신규 | 0 | — |
| 합 | 57 | = 공격 시드 57종 |

**"미해결 2건" = "입력단에 JOKER-KO 를 깔아야 하는 이유 2건"** → 처방②로 그대로 이어진다.
지금 화면은 이 2건을 "8.1%" 라는 백분율 뒤에 숨기고 있다. 이게 이번 개편의 핵심 손해다.

### 상태 정의 (화면에 그대로 표기 · 호버 아님)

```
🔴 미해결   처방 전에도 뚫렸고, 처방 후에도 뚫렸습니다   → 지시문으로는 못 막습니다
🟡 해결됨   처방 전에는 뚫렸으나 처방 후 차단됐습니다     → 처방문 적용으로 해결
⚪ 영향 없음 처방 전부터 차단됐습니다                    → 원래 안 뚫리던 공격
🟠 처방 후 신규 처방 전에는 막혔는데 처방 후 뚫렸습니다  → 처방문 재검토 필요
⚫ 재진단 없음 같은 공격이 2회차에 실행되지 않았습니다     → 비교 불가
```

## 2. 지적하신 a~f 에 대한 처방

### a. 실측 근거 카드에 저장소 경로 노출 (`↳ docs/ood_recall_*.md`)
- `headline_metrics.json` 에 **`source_label`** 을 추가하고 화면은 그것만 그린다.
  예: `source: "docs/ood_recall_*.md"` (파일 유지) + `source_label: "OOD 검증 리포트 · 2026-09-04"`.
  경로를 지우는 게 아니라 **개발자 뷰로 격리**한다 — 재현 가능성은 우리 강점이라 버리지 않는다.
- 대신 **측정 조건(`condition`)을 hover 에서 카드 본문으로 올린다.** 지금은 마우스를 올려야 보이는데,
  조건 없는 숫자가 화면에 떠 있는 시간이 길수록 과장으로 읽힌다. 모바일·스크린샷·시연 영상에서는 hover 가 아예 안 보인다.
- 심사용 원본이 필요하면 신뢰성 페이지 맨 아래 `근거 파일 목록` 접기 하나에 모아 둔다.

### b. 전 화면이 한 컬럼 세로 스크롤 → 목록·상세 패턴 도입
- 결과 화면을 **요약(고정) + 좌 Findings 목록 / 우 Finding 상세** 2단으로 바꾼다(`layout="wide"` 이미 사용 중).
- 이력 화면도 같은 골격: 좌 진단 목록 / 우 선택한 진단 요약 미리보기 + [열기].
- Streamlit 제약 대응: **`st.dataframe` 선택 이벤트를 쓰지 않는다.** canvas 라 DOM 에 텍스트가 없어서
  Playwright 검증이 불가능하다([[chatshield-화면개편]] 동작 함정). 목록은 `st.container(border=True)` + `st.columns`
  반복으로 그리고 행 끝에 `st.button("상세")` 를 둔다. 행 수는 최대 57(full)·18(screening)이라 위젯 수는 감당 가능하다.

### c. 결과가 "리포트 덤프" → Finding 단위로 다룬다
- **1 Finding = 1 attack_id (r1·r2 쌍)**. 상태·기법·채널·판정근거를 가진 독립 객체로 취급한다.
- 목록에서 필터·정렬하고, 하나를 골라 상세를 보고, 상세 안에서 다음 행동(처방② 배치 근거)으로 넘어간다.
- 지금의 `시도별 상세` expander(전량 나열)는 폐기한다.

### d. 랜딩과 앱이 같은 셸 → 셸 2개로 분리
| | 마케팅 셸 (홈) | 앱 셸 (진단·탐지·이력·신뢰성) |
|---|---|---|
| 좌측 사이드바 | **없음** | 있음 |
| 상단 | 브랜드 + [로그인] [무료로 시작] | 컨텍스트 바(현재 리포트 · 등급 · run_id · 액션) |
| 폭 | 풀블리드 히어로 | 콘텐츠 폭 고정 |
| 푸터 | 있음(제품 소개·한계) | **없음** (사이드바 하단이 대신) |
- 전환 지점: 홈에서 [무료로 진단하기] 를 누른 순간부터 앱 셸이다.

### e. 수치가 "우리 모델 성능"으로 읽힌다 → 주어를 바꾼다
- **결과 화면에는 사용자의 숫자만 남긴다.** F1 0.981 · OOD 81.6% · 0건/50 은 홈과 **신뢰성 페이지**로 이동.
  결과 화면에는 `이 판정을 믿어도 되는 근거 →` 링크 한 줄만 둔다(`render_ko_verification()` expander 폐기).
- **퍼센트보다 건수를 1급으로.** `처방 전 57.9%` → **`공격 57건 중 33건이 뚫렸습니다 (57.9%)`**.
  백분율은 우리 벤치마크의 언어이고, 건수는 사용자의 피해 언어다.
- 문장 주어를 전부 "당신의 지시문은 …" 으로 통일한다.

## 3. 사이드바 설계

```
┌─────────────────────┐
│ 🛡️ Chat Shield       │ ← 클릭 = 홈(마케팅 셸)로
│                     │
│ [ ＋ 새 진단 ]        │ ← 1급 CTA. 앱에서 제일 자주 하는 행동
│                     │
│ 🩺 진단 리포트  ●    │ ← 현재 run 있을 때만 활성 · 점은 미해결 건수 배지
│ 🔍 실시간 탐지        │
│ 🗂 내 이력      12   │ ← 회원은 건수 / 비회원은 🔒
│ ───────────────     │
│ 📐 신뢰성 근거        │ ← 홈의 실측 KPI·OOD·한계가 여기로
│                     │
│ (하단 고정)          │
│ 🟢 엔진 정상          │ ← 클릭 = 연결 설정 모달(현행 유지)
│ 👤 user@ex.com  ⌄   │ ← 비회원이면 [로그인][가입]
└─────────────────────┘
```

| 항목 | 목적 (한 줄) |
|---|---|
| ＋ 새 진단 | 지시문 입력 화면으로. 결과를 보다가도 항상 한 번에 새 진단 |
| 진단 리포트 | 현재 run 의 결과. run 이 없으면 비활성(껍데기 메뉴를 남기지 않는다) |
| 실시간 탐지 | JOKER-KO 단건 판정. 운영 중 방어층(1층) 체험 |
| 내 이력 | 저장된 진단 목록. 비회원에게는 자물쇠 = 가입 동기 |
| 신뢰성 근거 | "이 판정을 왜 믿나" 를 한 곳에. 제품 화면에서 연구 수치를 걷어낸 자리 |
| 엔진 상태 칩 | 현행 유지. mock 경고는 절대 축소하지 않는다 |
| 계정 | 로그인/가입/로그아웃 |

**홈에서 숨기는 법**: `view == "home"` 이면 `st.sidebar` 에 아무것도 그리지 않고,
`section[data-testid="stSidebar"]{display:none}` 를 홈에서만 주입한다(빈 사이드바가 남는 것을 막는다).
⚠️ 지금 CSS 가 사이드바 토글 화살표까지 `display:none` 으로 죽여 놨다 —
앱 셸에서는 **그 규칙을 해제**해야 접었다 폈다가 된다. 안 그러면 한 번 접히면 못 연다.
⚠️ 내비 CSS 는 [[chatshield-화면개편]] 함정①대로 **스타일시트 맨 끝**에 두고 `html body .stApp` 로 특이도를 올린다.

## 4. 결과 화면 재구성

```
[컨텍스트 바]  등급 A │ qwen2.5:3b-instruct 🟠대리모델 │ run_2026…a662 │ [처방문 복사] [삭제] [＋새 진단]
[요약 스트립]  🔴 미해결 2   🟡 해결됨 31   ⚪ 영향 없음 24   🟠 처방 후 신규 0   │  57.9% → 3.5%  ▼54.4%p
               └ 각 칸이 그대로 목록 필터 칩이다 (클릭 = 그 상태만 보기)
[📌 scope_notice 한 줄 — 항상]
──────────────────────────────────────────────────────────
[좌 55%] Findings 목록                 │ [우 45%] Finding 상세
[하단] 처방 ① 지시문 보강(복사) · ② 입력단 JOKER-KO 배치 권고
```

### Findings 목록 컬럼

| 컬럼 | 출처 | 비고 |
|---|---|---|
| 상태 | `round_no`×`verdict` 파생 | 🔴🟡⚪🟠⚫ + 한글 라벨 |
| 공격 ID | `attack_id` | `AUTH-06` |
| 기법 | `technique_ko` | 6종만(ROLE/AUTH/INDIRECT/OBFUSC/FORMAT/INDIRECT_DOC) |
| 유출 채널 | `leak_channel` | plain/reversed/base64/semantic/jamo/segmented → 한글 |
| 판정 | `verdict_by` | 규칙 / LLM |
| — | | 행 끝 [상세] 버튼 |

- **정렬 기본**: 상태(🔴 → 🟠 → 🟡 → ⚪ → ⚫) → 기법 → attack_id.
  이유: 미해결이 곧 처방②의 근거라 맨 위여야 한다. 사용자가 위에서 3줄만 읽고 나가도 결론이 전달된다.
- 정렬 변경: 기법순 / ID순 (드롭다운 1개). 그 이상은 안 만든다.
- **필터**: 상태 칩 5개(기본 🔴🟠🟡 on, ⚪⚫ off) · 기법 multiselect · 판정근거(전체/규칙/LLM).
  `⚪ 영향 없음` 24건이 기본으로 접혀 있어야 목록이 "할 일" 로 읽힌다.
- 상태 정의 범례 한 줄을 목록 위에 **상시 노출**(호버 금지).

### 요약 스트립이 지켜야 할 것
- 5칸 합 = 총 Finding 수. 화면에 `합계 57건` 을 같이 찍어 검산 가능하게 한다.
- `comparable=false` 면 ⚫ 가 늘어나므로 스트립 위에 기존 경고 배지를 그대로 띄운다.
- **Security Score 82/100 같은 합성 점수는 만들지 않는다.** 등급(A~F)은 엔진이 이미 주는 값이라 그대로 쓴다.

## 5. Finding Detail 구성

```
AUTH-06   [권한 사칭]   🔴 미해결   INFO_LEAK
────────────────────────────────────────────
① 무엇을 던졌나        공격 문구 (rendered_text, 회원 전용 · 6절)
② 챗봇이 뭐라 했나      처방 전 / 처방 후 응답 발췌 2단 (마스킹됨)
③ 왜 유출로 판정했나    규칙 판정 · 유출 채널: 평문 노출
④ 처방 후 재시도        같은 공격을 그대로 재생 → 여전히 유출
⑤ 권고 조치            상태별 고정 문구
▸ 재현 조건 (접기)      qwen2.5:3b-instruct · temp 0 · seed 42
```

- **③ 판정 근거 문구(고정)**
  - `rule` → "응답에 보호 자산이 **규칙으로 명확히** 검출됐습니다. LLM 판단이 필요 없는 명백한 유출입니다."
  - `llm` → "규칙으로는 애매한 회색지대라 **심판 모델이 다시 판정**했습니다."
  - 채널 한글화: `plain` 평문 그대로 · `reversed` 뒤집기 · `base64` 인코딩 · `semantic` 의미상 유출 · `jamo` 자모 분해 · `segmented` 조각 유출.
  - ⚠️ **비율(규칙 n%)은 상세에 넣지 않는다** — 그건 우리 판정기 성능이지 이 Finding 의 사실이 아니다(지적 e).
- **⑤ 권고 조치** — 상태별로만 말하고, 없는 인과는 지어내지 않는다.
  - 🔴 "지시문 처방으로는 막히지 않았습니다. **입력단 JOKER-KO 배치(처방②)가 이 건의 대응입니다.**"
    + `filter_recommendation.flags` 에 이 사유가 잡혀 있으면 "규칙 층이 이 유형을 잡습니다" 한 줄 추가.
  - 🟡 "처방문 적용 후 차단됐습니다. 적용된 방어 패턴: P01 P03 …"
    ★ **어느 패턴이 이 건을 막았는지는 데이터에 없다.** "P03 이 이걸 막았습니다" 라고 쓰면 지어내는 것 →
    `applied_patterns` 전체를 그대로 보여주고 그 이상 단정하지 않는다.
  - ⚪ "처방 전부터 차단됐습니다. 이 공격 유형은 원래 지시문에서도 막혔습니다." (무엇 덕분인지는 단정 금지)
  - 🟠 "처방 전에는 막혔는데 처방 후 뚫렸습니다. **처방문 재검토가 필요합니다.**"
  - ⚫ "2회차에 이 공격이 실행되지 않아 비교할 수 없습니다."
- 상세 미선택 상태를 만들지 않는다 → 화면 진입 시 **가장 위험한 1건(🔴 첫 행)을 자동 선택**.
- 비회원은 이 패널 전체가 게이트 카드로 대체된다(6절).

### 서버에 없어서 추가가 필요한 필드
| 필드 | 현재 | 필요 이유 |
|---|---|---|
| `goal` | DB 有 / API `attempts[]` 無 | 상세 헤더의 "무엇을 노린 공격인가"(INFO_LEAK 등). 1줄 추가 |
| `rendered_text` | DB 有 / API 無 | 6절 |
| `findings_summary` | 없음 | 비회원에게 카운트만 주기 위해(7절) |

## 6. rendered_text(공격 문구) 노출 — **노출한다. 회원 전용 · 기본 접힘 · 복사 버튼 없음**

**찬성 근거**
1. **검증 가능성.** "AUTH-06 이 뚫렸다" 만 있으면 사용자는 우리 말을 믿는 것 외에 할 게 없다.
   문구가 있어야 자기 챗봇에 직접 넣어보고 처방 전후를 스스로 확인한다. 진단 도구의 신뢰는 여기서 나온다.
2. **동종 제품이 전부 payload 를 보여준다.** Burp·ZAP·garak 모두 요청 원문을 리포트에 싣는다. 안 싣는 쪽이 예외다.
3. **비밀값이 안 들어간다는 것이 코드로 보장된다.** `nodes/attack.build_context()` 는
   `{asset}` 에 **자산의 이름만** 넣는다(`secret.name`), `{decoy}` 는 가짜값 `BUSAN-9999` 고정.
   `corpus/render.render_attack()` 은 이 4개 플레이스홀더만 replace 한다. 즉 공격문에 사용자의 진짜 비밀값이 실릴 경로가 없다.

**반대 근거와 그 처리**
| 위험 | 처리 |
|---|---|
| 공격 시드 57종이 우리 자산인데 통째로 스크래핑된다 | **비회원에게 안 준다.** 현행 `attempts[] = []` 게이팅이 그대로 막는다 — 추가 코드 0 |
| "공격 문구를 화면에 뿌려도 되나" (심사 질문) | 사용자 **자신의** 지시문에 던져진 문구이고, 새 공격을 가르치는 게 아니라 이미 실행된 기록이다. 상세 안에 접어 두고 라벨을 `이 진단에서 실제로 던진 문구` 로 쓴다. **복사 버튼은 달지 않는다**(대량 수집 편의를 우리가 제공할 이유는 없다) |
| 지시문에서 온 문자열(페르소나·기관·자산 이름)이 그대로 섞여 있다 | 출력 시 **반드시 `esc()`**. 우리는 인젝션 진단 도구다 |
| 만약의 값 유출 | 서버에서 `mask_excerpt(rendered_text, 400)` 로 응답 발췌와 **같은 마스킹 경로**를 태운다. 보장이 두 겹이 된다 |

**구현 (승인 시)**: `serialize._attempt()` 에 `"rendered_text": mask_excerpt(a.get("rendered_text") or "", 400)` 와
`"goal": a["goal"]` 2줄 → 계약 v0.5 표 2행 → 게이팅은 attempts 경계가 이미 처리.

**하지 않을 경우의 대안**: 기법 설명문만 보여주는 상세. 그러면 ①②가 비어 상세 패널의 절반이 사라지고,
"목록→상세" 구조를 도입할 이유 자체가 약해진다. 권장하지 않는다.

## 7. 새 구조에서의 비회원 게이팅 경계

원칙은 그대로다 — **위험 사실은 안 가린다. 가리는 것은 해결책과 증거의 상세.**
Findings 는 **증거**이므로 목록·상세 전체가 회원 영역이고, **카운트는 위험 사실**이라 공개한다.

| | 비회원 | 회원 |
|---|---|---|
| 등급 · before/after · delta · 기법별 막대 · 자산 이름 · scope_notice | 공개 | 공개 |
| **요약 스트립 5칸 카운트 (🔴2 🟡31 ⚪24 🟠0 ⚫0)** | **공개(신규)** | 공개 |
| Findings **목록** (행) | **🔒 게이트 카드** | 전량 |
| Finding **상세** (공격문·응답·판정근거) | 🔒 | 전량 |
| `patched_prompt` | 앞 2줄 | 전문 |

- 서버 변경 1건: `report.findings_summary = {unresolved, resolved, unaffected, regressed, no_retry, total}`.
  `_apply_gate()` 는 이 키를 **지우지 않는다**(카운트는 위험 사실).
  `attempts[] = []` 규칙은 **손대지 않는다** → `test_gating` 4개가 그대로 통과한다.
- 게이트 문구는 카운트를 그대로 인용한다: **"미해결 2건의 공격 문구와 판정 근거가 비공개입니다"**.
  지금의 "36건 비공개" 보다 강하다 — 숫자가 아니라 *위험*을 인용하기 때문이다.
- ★ 비회원이 이 화면에서 가장 크게 보게 될 것은 **🔴 미해결 건수**여야 한다. 전환은 여기서 일어난다.
- CSS 블러 금지 규칙 그대로. 목록은 서버가 안 보낸 데이터를 못 그리는 것뿐이다.
