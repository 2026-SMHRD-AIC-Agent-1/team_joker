# Chat Shield 웹

사용자 화면은 React + TypeScript + Vite로 전환했습니다. Node.js는 개발 서버와 빌드,
통합 실행을 담당합니다. 모델 추론·파이프라인·저장소·인증은 기존 Python FastAPI를 사용합니다.

## 실행

처음 설치, 평소 실행, 포트 충돌 해결은 [프로젝트 README의 실행 안내](../README.md#7-5분-안에-돌려보기)를 참고하세요.

프로젝트 루트에서 Python 의존성 `pip install -e ".[web]"`를 설치한 뒤:

```sh
cd web
npm ci
npm run dev:all
```

개발 화면은 `http://127.0.0.1:5173`입니다. API를 이미 실행 중이면 `npm run dev`를 씁니다.
배포 형태는 `npm run build` 후 `npm start`이며 `http://127.0.0.1:8000`에서 열립니다.
한 서버에서 API와 웹을 함께 제공하므로 결과 URL 새로고침에도 별도 라우팅 설정이 필요 없습니다.

실행 중인 터미널은 열어 두고, 종료는 `Ctrl+C`로 합니다. `5173` 또는 `8000` 포트 충돌이 나면 기존 서버를 실행한 터미널에서 종료한 뒤 다시 실행하세요. 브라우저를 닫아도 서버는 종료되지 않습니다.

## Streamlit 기능 대응

| 기능 | 웹 화면 |
|---|---|
| 서비스 소개·무료 진단 시작 | `/` |
| 로그인·가입·이전 체험 복귀 | `/login` |
| 지시문 입력·예시 선택/덮어쓰기 확인·모델·정밀도·BYOK·호출량 고지 | `/diagnose` |
| 진행 단계·대기·결과·실패·진단 불가·삭제 | `/runs/:runId` |
| 유출 증거·필터·통계·보강안 복사·변경 비교·게이팅 | 진단 리포트 내부 |
| 공격별 전후 응답·판정 근거 | `/runs/:runId/f/:fid` |
| 최근 진단·조치 필요·등급·추이·검증 근거 | `/dashboard` |
| 전체 진단·검색·상태 필터·페이지 이동 | `/history` |
| 단건 탐지·예시·리포트 공격 전달·ML/규칙 결과 | `/detect` |
| 엔진 상태·모델 목록·검증 근거·계정 | `/settings` |

Streamlit의 API 주소 입력은 서버 환경 변수 `JOKER_API_URL`(Vite 개발 프록시)로 대체합니다.
브라우저의 인증 헤더를 임의의 서버로 전송하지 않도록 `/api`와 같은 출처만 사용합니다.
`JOKER_API_PORT`로 통합 실행의 API 포트, `JOKER_PYTHON`으로 Python 실행 파일을 선택합니다.

## 확인

```sh
npm test
npm run build
# 프로젝트 루트에서
.venv/bin/python -m pytest
```

- 웹 테스트: 응답 경쟁, 통신 오류 뒤 폴링 재개, 전체 이력 페이지 이동, 게스트 중복 발급 방지,
  진행 중 로그인한 진단의 완료 후 귀속, 기존 리포트/인증/지표 테스트.
- `tests/test_web_serving.py`: 정적 파일·상세 주소·알 수 없는 API·소유자별 실행 목록,
  Mock 엔진으로 체험→가입→귀속→전체 리포트→삭제→로그아웃 통합 검증.
- 실제 유료 BYOK 호출의 성공 여부와 모델 품질은 해당 키/엔드포인트로 별도 검증해야 합니다.
- 탐지에는 학습 모델과 Python `.[detect]` 의존성이 필요합니다. 없으면 준비 상태와 안내가 표시됩니다.
- 진행/실패 상태는 서버 메모리에 있고 완료 결과는 DB에 있습니다. 서버 재시작 시 진행 작업은 복구되지 않습니다.
- 어두운 남색 테마와 상단 메뉴를 사용합니다. 결과는 요약·발견된 문제·보강안·자세한 기록으로 나뉘며 선택한 구역은 URL에 유지됩니다.
- 작은 화면에서는 메뉴가 접히며, 운영체제의 동작 줄이기 설정을 따르면 전환 애니메이션이 꺼집니다.
